## Theory
Lexical analysis is one of the first stages in the process of compiling or interpreting a programming language. During this stage, the input text is scanned and divided into meaningful units called tokens. The component responsible for this task is called a lexer, scanner, or tokenizer.

A token represents a category of lexical elements such as numbers, operators, parentheses, or reserved words. Each token usually contains a type and sometimes a value. The type identifies the category of the lexeme, while the value stores the exact text that was recognized.

The lexer reads the input character by character and groups them according to the rules of the language. For example, digits may form numbers, certain symbols represent operators, and specific letter combinations may represent predefined functions.

Lexical analyzers are usually implemented using finite automata because they efficiently recognize patterns in sequences of characters. By transforming the raw input into tokens, the lexer simplifies the work of later stages such as parsing and semantic analysis.

In this laboratory work, a simple lexer is implemented that can recognize integers, floating point numbers, arithmetic operators, parentheses, and trigonometric functions such as sin and cos.

## Implementation description

The implementation is organized into four main components: TokenType, Token, Lexer, and Main. Each component has a specific responsibility in the lexical analysis process. The program is written in Java and does not rely on external libraries for lexical processing.

### TokenType enum

The TokenType enumeration defines all possible types of tokens that can be recognized by the lexer. These include numeric types, arithmetic operators, trigonometric functions, parentheses, and the end-of-file marker.

Example: token type definitions

```java
public enum TokenType {

    INTEGER,
    FLOAT,

    PLUS,
    MINUS,
    MULTIPLY,
    DIVIDE,

    SIN,
    COS,

    LPAREN,
    RPAREN,

    EOF
}
```
This structure makes the program easier to maintain and extend, because new token categories can be added easily if the language is expanded.


### Token class

The Token class represents a single lexical unit generated by the lexer. Each token stores its type and the value that was read from the input text.

Example: token representation

```java
public class Token {

    public TokenType type;
    public String value;

    public Token(TokenType type, String value) {
        this.type = type;
        this.value = value;
    }

    @Override
    public String toString() {
        return type + " : " + value;
    }
}
```

This class provides a simple way to store and display tokens produced by the lexer.


### Lexer class

The Lexer class performs the lexical analysis by reading the input text character by character and generating tokens based on predefined rules. The lexer maintains the current position in the text and the current character being analyzed.

Example: storing the input and current position

```java
private String text;
private int pos;
private char currentChar;
```
The lexer includes helper methods for advancing through the input, skipping whitespace, recognizing numbers, and identifying function names.

Example: advancing to the next character

```java
private void advance() {
    pos++;

    if (pos >= text.length()) {
        currentChar = '\0';
    } else {
        currentChar = text.charAt(pos);
    }
}
```
This method moves the lexer forward in the input string.

### Number recognition

The lexer recognizes numeric values using the number() method. It reads consecutive digits and optionally a decimal point to distinguish between integers and floating point numbers.

Example: number detection

```java
private Token number() {
    StringBuilder result = new StringBuilder();

    while (currentChar != '\0' &&
            (Character.isDigit(currentChar) || currentChar == '.')) {

        result.append(currentChar);
        advance();
    }

    if (result.toString().contains(".")) {
        return new Token(TokenType.FLOAT, result.toString());
    }

    return new Token(TokenType.INTEGER, result.toString());
}
```
This allows the lexer to correctly classify numbers such as 3 or 4.5.


### Identifier recognition

The lexer also recognizes identifiers representing trigonometric functions. In this implementation, the supported functions are sin and cos.

Example: identifier detection

```java
private Token identifier() {
    StringBuilder result = new StringBuilder();

    while (currentChar != '\0' && Character.isLetter(currentChar)) {
        result.append(currentChar);
        advance();
    }

    String value = result.toString();

    if (value.equals("sin"))
        return new Token(TokenType.SIN, value);

    if (value.equals("cos"))
        return new Token(TokenType.COS, value);

    throw new RuntimeException("Unknown identifier: " + value);
}
```
If an unknown identifier is encountered, the lexer throws an error.

### Token generation

The method getNextToken() is responsible for scanning the input and producing the next token.

Example: token generation logic

```java
public Token getNextToken() {

    while (currentChar != '\0') {

        if (Character.isWhitespace(currentChar)) {
            skipWhitespace();
            continue;
        }

        if (Character.isDigit(currentChar))
            return number();

        if (Character.isLetter(currentChar))
            return identifier();
```
The method continues until the entire input string has been processed.

### Main class

The Main class demonstrates how the lexer works by processing a sample mathematical expression.

Example: main method

```java
public static void main(String[] args) {

    String text = "sin(3 + 4.5) * cos(2)";

    Lexer lexer = new Lexer(text);

    Token token = lexer.getNextToken();

    while (token.type != TokenType.EOF) {
        System.out.println(token);
        token = lexer.getNextToken();
    }
}
```
This part of the program prints each token generated by the lexer.

## Conclusions

In this laboratory work, a simple lexical analyzer was implemented in Java. The lexer reads an input expression and converts it into a sequence of tokens that represent the fundamental elements of the language.

The implementation supports integers, floating point numbers, arithmetic operators, parentheses, and trigonometric functions such as sin and cos. By scanning the input character by character and grouping them into tokens, the lexer demonstrates how lexical analysis works in practice. This process simplifies further stages of language processing because instead of working with raw text, the program works with structured tokens that clearly represent the components of the expression.

During the implementation, different methods were created to handle specific tasks such as advancing through the input text, skipping whitespace, recognizing numbers, and identifying predefined functions. This modular approach improves the clarity and maintainability of the code and makes it easier to extend the lexer with additional tokens or language constructs in the future.

The execution results confirm that the lexer correctly identifies the tokens from the input expression and prints them in the correct order. This demonstrates that the lexical analysis stage successfully transforms the raw input into a structured representation that could later be used by a parser or interpreter.

Overall, this experiment shows how theoretical concepts from formal languages and finite automata can be applied in real programming tasks such as building components of a compiler or interpreter. Understanding lexical analysis is an important step in the study of language processing systems and provides the foundation for implementing more advanced stages such as parsing and semantic analysis.
