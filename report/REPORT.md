## Theory
Parsing represents the process of analyzing a sequence of tokens in order to determine its syntactic structure according to a given grammar. It is a fundamental step in language processing and compilation, as it transforms a linear sequence of symbols into a structured representation that reflects the hierarchical relationships between elements.

A common result of parsing is the construction of a parse tree, which explicitly represents every rule used during derivation. However, in practice, a more compact and meaningful structure is often preferred — the Abstract Syntax Tree (AST). Unlike a parse tree, an AST omits unnecessary syntactic details (such as parentheses or intermediate grammar rules) and focuses only on the essential components of the expression.

The parsing process typically relies on a formal grammar that defines how valid expressions can be formed. In this laboratory work, a recursive descent parsing approach is used. This method implements the grammar directly in code through a set of mutually recursive functions, each corresponding to a non-terminal in the grammar.

The grammar is structured in a way that enforces operator precedence and associativity. For example, expressions are decomposed into terms and factors, ensuring that multiplication and division are evaluated before addition and subtraction. This hierarchical decomposition allows the parser to correctly interpret complex mathematical expressions.

During parsing, tokens produced by the lexical analyzer are consumed sequentially, and corresponding AST nodes are created. Each node represents a specific construct:

- binary operations (e.g., addition, multiplication),
- unary operations (e.g., trigonometric functions),
- numeric values.

The resulting AST is a tree-like structure in which internal nodes represent operations, while leaf nodes represent operands. This structure is particularly useful for further processing, such as evaluation, optimization, or visualization.

In addition, ASTs provide a clear abstraction over the syntax of the input, making them widely used in compilers, interpreters, and static analysis tools. Their hierarchical nature allows efficient traversal and manipulation, enabling advanced operations on expressions and programs.

## Implementation description
The implementation is organized into several main components: Lexer, Token, TokenType, Parser, AST node hierarchy, and visualization modules. Each component has a specific role in transforming an input expression into an Abstract Syntax Tree (AST). The program is written in Java and relies only on standard libraries, including Java Swing for graphical visualization.

### Lexer class

The Lexer class is responsible for the lexical analysis phase. It processes the input string character by character and converts it into a sequence of tokens.

Example: lexer structure and behavior

```java
public class Lexer {

    private String text;
    private int pos;
    private char currentChar;

    public Lexer(String text) {
        this.text = text;
        this.pos = 0;
        this.currentChar = text.charAt(pos);
    }
}
```
The lexer uses regular expressions to identify:

- integers and floating-point numbers
- arithmetic operators (+, -, *, /)
- parentheses
- identifiers such as sin and cos

It also skips whitespace and throws an error when encountering invalid characters.


### Token and TokenType classes

Tokens are represented using the Token class, which stores both the type and value of each token.

```java
public class Token {
    public TokenType type;
    public String value;
}
```
The TokenType enumeration defines all possible categories of tokens:
```java
public enum TokenType {
    INTEGER, FLOAT,
    PLUS, MINUS, MULTIPLY, DIVIDE,
    SIN, COS,
    LPAREN, RPAREN,
    EOF
}
```
This separation allows the lexer and parser to work with clearly defined token types.

### Parser class

The Parser class performs syntactic analysis using a recursive descent parsing approach. It consumes tokens produced by the lexer and builds the AST step by step.

Example: parsing structure

```java
public AST parse() {
    return expr();
}
```
The grammar is implemented using hierarchical methods:

- expr() → handles addition and subtraction
- term() → handles multiplication and division
- factor() → handles numbers, parentheses, and functions

This structure ensures correct operator precedence and associativity.

### AST node classes

The Abstract Syntax Tree is built using a hierarchy of classes derived from a base abstract class.

```java
public abstract class AST {
}
```
The following node types are implemented:

- Binary operation node:
```java
public class BinOp extends AST {
    public AST left;
    public Token op;
    public AST right;
}
```
- Unary operation node:
```java
public class UnaryOp extends AST {
    public Token op;
    public AST expr;
}
```
- Numeric node:
```java
public class Num extends AST {
    public Token token;
    public double value;
}
```
These classes represent the structure of expressions in a hierarchical way, where internal nodes correspond to operations and leaf nodes correspond to values.

### AST Visualization
A graphical representation of the AST is implemented using Java Swing.

The ASTDrawPanel class is responsible for rendering the tree:

```java
public class ASTDrawPanel extends JPanel {
    private AST root;
}
```
Each node is drawn as a colored circle depending on its type:

- blue for binary operations
- orange for unary operations
- green for numeric values

The ASTWindow class creates the window and displays the visualization.

### Main class
The Main class demonstrates the complete workflow of the application.

Example:

```java
String text = "sin(3 + 4.5) * cos(2)";

Lexer lexer = new Lexer(text);
Parser parser = new Parser(lexer);

AST tree = parser.parse();
```
It:

- defines the input expression
- performs lexical analysis
- parses the tokens
- constructs the AST
- visualizes the resulting tree
